抽象这个词，大家多少都了解：抽象就是理解不了的东西呗！抽象画派、毕加索……下面以一个程序员的角度谈一下**抽象**。

### 什么是抽象？

抽象就是从不同的事物之间抽取出相同点。往往能力越强，抽象能力就越强，认知的维度就越高。

### 为什么要抽象？

世间万物都在变化。如果具有了抽象能力，能在变化中找到不变，那么在解决问题时只需要更改那些需要变化的元素，从而减少工作量。

例如，软件开发中的需求不断变化。有人说，杀死一个程序员，不是给他一把刀，而只需要改 3 次需求。程序员设计程序时，能够把这些变化的需求和不变的本质分析出来，设计出相对抽象的程序，选择适当的数据结构和设计模式，对可变的元素进行重写而不用改动其他依赖，那么是否能避免一部分全部推倒重来的事情发生呢？

### 抽象的应用或表现

软件工程学中的 OOAD（Object-Oriented Analysis and Design），以及软件编程思想中的 OOP（Object-Oriented Programming），它们的第一要素都是抽象。抽象的维度越合适，设计的程序就越易用。

例如，一个小超市要做一款商品管理系统，暂时只有白酒。

程序员 A 针对**白酒**分析属性，设计了一个白酒类。

程序员 B 针对**酒**分析属性，设计了一个酒类，并加入 **type** 属性来区分白酒或其他类型的酒。

程序员 C 针对**饮品**分析属性，设计了一个饮品类，加入 **type** 区分酒和其他饮品，并将原来的 type 变为 **color**，只有 type 是酒的时候才拥有 color 属性。

程序员 D 针对**商品**分析属性，设计了商品类，加入商品类型 **type** 区分饮品和其他商品，将 C 的 type 变为 drinkType，只有 type 是饮品的时候才拥有 drinkType 属性。

Later……超市挣钱了，变成了大超市，不仅卖白酒，也开始卖啤酒和红酒了。那么程序员 A 设计的程序很遗憾地被淘汰了！

又 later……超市继续扩大，不仅卖酒，而且开始卖牛奶、矿泉水、饮料等饮品，程序员 B 设计的程序被淘汰！

又又 later……超市不仅卖饮品，还卖起了水果、日用品，程序员 C 设计的程序也被淘汰！

从上面的例子中可以看到，程序员 D 的程序最棒，因为他的抽象层级比其他三个都要高，所以面对变化也可以从容应对，调整不会太大！

### 抽象的维度越高越好吗？

这个要根据场景选择合适的抽象维度，并不完全是越抽象越好。因为抽象最终要应用到使用，使用必然要具体。要找到具体对象，步骤就会**繁琐**，会**增加复杂度**。

从上面的例子来说，超市老板的需求最大就是超市可以满足的特征，例如衣食、日用等商品。他不可能在超市卖所有种类的东西，不然世界就是这个老板的了。如果程序员的抽象维度是所有“商品”（并非上面的超市商品），那么就要包括其他类型商品：飞机、大炮、汽车、绣花针等。程序员就要分 n 种类型，程序要操作一个商品，需要检查 n 个层级才能找到对应的商品，程序会很慢甚至超出等待。过几天老板就不用这个系统了，因为还没有自己找得快呢！

所以，抽象能力是必不可少的。抽象能力越高，说明你站的角度越高，思考得就越高，这在生活和工作当中很有帮助。不然孔子、老子这样的人怎么能够成为大智者呢？老子的“道”你又是否懂呢？
